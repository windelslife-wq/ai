# Security model

Own `fp_users` ADMIN/VIEWER role boundary; only ADMIN enters admin routes. Passwords: scrypt with per-user 32-byte random salt; sessions: random 256-bit cookie, HMAC-SHA256 lookup key using mandatory production SESSION_SECRET, HttpOnly/Secure/SameSite=Strict, eight-hour expiry. Session state and one-time per-refresh CSRF token hash stored in database. Login throttled (8/15min/IP), API 120/min/IP. Helmet CSP, origin and Fetch Metadata rejection, JSON size limit, parameterized SQL (settings column names are from an internal allowlist), no CORS wildcard. Require HTTPS/TLS at hosting proxy and `NODE_ENV=production`; `trust proxy=1` assumes exactly one trusted cPanel reverse proxy. Verify this before deployment; if the proxy is not trusted, configure infrastructure accordingly. No public endpoint returns provider key, password, session hash or CSRF token (except authenticated bootstrap/login).

Operational: keep `.env` outside document root, rotate provider/session/database secrets after compromise, grant DB user access only to the new database, restrict shell/crontab permissions, never print credentials or payloads in logs, monitor sync and system logs, back up and restore-test both DB and secret material. Rate limits are per-process memory and not coordinated across multiple Node workers; use one worker per installation or add a shared limiter. No password reset or multi-factor auth in this release: provision accounts through protected CLI and apply host/operator controls. No explicit logout for public visitors because only admins can log in.

Honesty: API-Football supplied odds are provenance-checked by the ingestion boundary, not cryptographically signed bookmaker attestations. Bookmaker price availability/freshness depends on subscription and provider update timestamps. Not an audited betting exchange.
