# REST API v1

JSON, UTC ISO timestamps. Error format `{ "error": { "code": "..." } }`. All list endpoints accept `page` (1..10000) and `limit` (1..100), default 1/20. Public routes: `GET /api/fixtures`, `/api/odds`, `/api/predictions`, `/api/ticket/today`, `/api/tickets/history`, `/api/tickets/:id`. Ticket today returns a published ticket with immutable snapshots, or `{status:"NO QUALIFYING TICKET",message,generation?}`. Public odds show only available, recently observed Over 1.5. Public predictions only for published tickets.

Auth: `POST /api/auth/login` `{email,password}` creates an HttpOnly session and returns `{user,csrfToken}`; `GET /api/auth/me` checks session; `POST /api/auth/csrf` rotates a CSRF token for an authorized admin session after refresh; `POST /api/auth/logout` needs `x-csrf-token`. All admin endpoints require ADMIN session, all admin mutations require CSRF header. No frontend-submitted odds, result, model score or ticket contents are accepted. Same-origin HTTPS required in production.

Admin: `GET /api/admin/dashboard`, `POST /api/admin/generate-ticket` (body ignored; one attempt per UTC date; duplicate returns previous generation), `GET /api/admin/generation-report` (latest actual persisted stage/report), `POST /api/admin/tickets/:id/publish`, `POST /api/admin/tickets/:id/unpublish`, `GET /api/admin/settings`, `PUT /api/admin/settings` (integer allowlisted fields only), `GET /api/admin/system-logs`, `GET /api/admin/api-status`, `GET /api/admin/analytics`, `GET /api/admin/tickets`, `GET /api/admin/tickets/:id`, `GET /api/admin/predictions`. Locked values: market OVER_1_5, min/max odds 2.00/4.00, automatic generation false.

`generate-ticket` is synchronous (provider-bound); a concurrent admin can poll the report. A client HTTP timeout does not imply server cancellation; retrying returns the same day's generation id, not a second ticket. Failed attempts also prevent another same-day generation; an operator must investigate/reconcile manually. No unaudited reset endpoint is provided.
