# Independent cPanel deployment (requires actual Node support)

Confirm host offers **Node.js Application Manager** with Node 22+, SSH/terminal or equivalent application console, cPanel MySQL/MariaDB with InnoDB/JSON/CHECK, outbound HTTPS to `v3.football.api-sports.io`, and cron with a usable Node binary. Ordinary PHP-only cPanel is insufficient. Keep this app outside PHP public_html and serve a dedicated HTTPS subdomain through Application Manager. Root: `/home/CPANEL_USER/apps/football-predictions` (or copied equivalent); startup file `server.js`; command `node server.js`; bind-provided `PORT` on 0.0.0.0. Do not point a second app at the existing PHP domain without a documented reverse proxy.

1. Back up first. Create a NEW MySQL database and a dedicated user with privileges only on it. Never import root `database/production.sql` into this database.
2. Upload the app excluding node_modules. In its directory run `npm ci --workspaces=false` (if npm supports it; this is a workspace child). Configure environment in Application Manager: NODE_ENV, PORT (manager may assign), DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD, API_FOOTBALL_KEY, SESSION_SECRET. Set a random unique SESSION_SECRET >=32 characters. Do not commit `.env`.
3. Run `node server/migrate.js` with the same DB environment. Migration ledger checks SHA-256. Create admin with `FP_ADMIN_PASSWORD` in a protected terminal environment and `node server/create-admin.js admin@example.com`; clear variable afterwards. Use `read -rsp 'Admin password: ' FP_ADMIN_PASSWORD; echo; export FP_ADMIN_PASSWORD` to avoid entering a secret in shell history, then run the CLI and `unset FP_ADMIN_PASSWORD`. Never pass password as a command-line argument. Verify outbound API access and cron budget before enabling jobs.
4. Configure SSL via cPanel/AutoSSL; ensure reverse proxy sends secure protocol and host. Verify `GET /api/ticket/today` and admin login over HTTPS. Restart through Node.js Application Manager after changes; check its logs and `fp_system_logs`/`fp_sync_logs`.
5. Configure cPanel cron with absolute Node path and application root. Example `cd /home/CPANEL_USER/apps/football-predictions && /path/to/node --env-file=/home/CPANEL_USER/private/football.env server/jobs/cli.js fixtures`. Keep private env outside document root, mode 0600. Separate schedules: fixtures hourly, odds every 10–15 minutes, statistics every 4–6 hours, results every 30 minutes, freshness hourly, health hourly. Cron process must have DB/API env even if Application Manager has them separately. Adjust frequencies and `LIMIT 30` against actual Pro plan quota; no worker daemon needed. **Never schedule `generate-ticket`**: only authenticated manual admin POST can generate.
6. Nightly database backups and protected copy of environment, plus tested restore. Monitor old cache rows/sessions/log growth and purge through DBA maintenance with retention policy; never truncate ticket/audit history casually.

Troubleshooting: 403 HTTPS_REQUIRED means proxy trust/SSL mismatch; 403 CSRF_INVALID means refresh admin UI for a new token; 429 means provider or app throttling; empty odds mean the provider may not cover Over 1.5 for that fixture; missing team form means statistics job/plan failed; no ticket is a valid outcome. If host lacks Node 22/cron/outbound API/MySQL JSON, move this isolated application to a compatible host rather than silently falling back to PHP or fabricated data. cPanel hosting has **not** been verified in this workspace.
